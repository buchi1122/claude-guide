Cowork と Code の違い

軸CoworkClaude Code
入口デスクトップアプリ（画面）ターミナル・エディタ
得意資料・整理・文書・調査コードを書く・直す・テスト
ファイルつないだフォルダプロジェクト全体に広く
使う人非エンジニア開発する人

目安：gitで管理する"開発"ならCode、それ以外はCowork。同じ記憶の家（Vault）を両方から共有できるので、乗り換えでなく使い分けになる。

    基本の使い方

    頼む → 承認する → 実行

    1
    ふつうの言葉で頼む
    「ログイン画面を作って」「このバグを直して」。専門用語は要らない。
    2
    変更案を承認
    Claudeが計画と差分を提示。人はそれを見てOKを出すだけ。
    3
    実行・テスト
    Claudeが書いて動かし、失敗すれば自分で直す。結果を報告。

    人は変更計画を承認するだけ。行単位のコードレビューはしなくてよい。正しさはテストと「戻せる復元点」で担保する——読む代わりに、検証させる。

    MCP10 / 12
    安全に使う

    広い権限は、確認で守る

    • 1破壊的操作は実行前に確認が入る（消す・上書き・送信）。中身を見てからOK
    • 2git で復元点を作っておく。失敗しても丸ごと戻せる
    • 3認証・課金・削除など重い操作は自分で最終判断

    仕組みで守るなら hooks ── 例：git reset --hard 等の危険コマンドを機械的にブロックする"強制執行層"。この仕組み自体もClaudeに作らせられる。

    現場の記録push用の認証をコマンドラインに入れず、コミットまでAI・pushは自分の1クリックという分担に落ち着いた。不便の産物だが、結果的に「本番反映の直前に人間の関門が1つ残る」——安全設計として理にかなっていたので、そのまま運用にした。
